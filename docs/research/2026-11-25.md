## Ollama now uses Intel graphics out of the box

*New technology* – Since version 0.30 Ollama switches on Vulkan graphics acceleration by default, which covers Intel integrated and Arc graphics.

Ollama is the optional local model runner behind Ask PLEX on the laptop. Its June 2026 release turned on Vulkan by default, so AMD and Intel graphics are used without extra vendor libraries. The same release improved loading of GGUF model files through llama.cpp.

For PLEX this means Ask PLEX answers can run on the laptop's Intel graphics instead of only the processor, which usually gives quicker replies and leaves the processor free for the rest of the app.

How: update Ollama on the laptop to 0.30 or later, run a short question and watch the graphics load in Task Manager. A GGUF file copied onto the laptop can be added offline with a one-line Modelfile (FROM ./file.gguf) and ollama create. The sources give no speed figures for Intel graphics, so time a few typical questions before and after. Effort: under an hour.

## OpenVINO 2026.3/2026.4: bigger models on 16 GB

*New technology* – Intel's OpenVINO can now keep part of a large mixture-of-experts model on disk, so a 30-billion-parameter Qwen model runs on a 16 GB machine.

OpenVINO is Intel's own engine for running models on Intel processors, graphics and the NPU. Version 2026.3 (August 2026) added disk offloading for mixture-of-experts models; Intel says this lets Qwen3-30B-A3B work on systems with 16 GB of memory. Version 2026.4 (September 2026) made Gemma 4 faster on Intel graphics and added faster guessing-ahead decoding for Gemma 4 and Qwen3.5/3.6.

For PLEX this is the alternative to Ollama when answers need a stronger model than the small ones that fit fully in memory, for example summarising a whole week of reports.

Caution from the release notes: some NPU drivers crash; Intel recommends NPU driver 32.0.100.5540 or later. Try it on the laptop as a side test before relying on it. Effort: half a day to install and compare with Ollama.

## Hidden-risk tagging of report remarks

*Idea* – Operators now use small fine-tuned language models to find risks written into report lines that were booked as productive time.

SLB describes tagging daily drilling report remarks into 13 risk classes, aimed at lines coded as normal operations that still describe a problem. A fine-tuned 7-billion-parameter model agreed with engineers on 94% of 342 checked remarks from 180 reports (about 96% after a second review). At the IADC technology forum in March 2026, a talk on retrieval-based IADC code assignment across four rigs reported more than half the report preparation time saved.

For PLEX this fits the invisible lost time analytics: lines booked as productive but mentioning waiting, repeat runs, or equipment trouble are exactly where invisible lost time hides.

How: keep a fixed list of risk tags, hand-label a few hundred past remarks once, then let the local model (Ollama) suggest a tag for each new line with those labelled examples in the prompt. Show suggestions for the Company Man to accept or reject and feed the answers back into the examples. Effort: two to three days.

## Data audit and job pace with conformal limits

*Idea* – Conformal control limits flag an unusual job time or data value without assuming the numbers follow a bell curve.

A December 2025 paper shows how to build control-chart limits from a set of past normal values: score each value by its distance from the median, and take the matching rank as the alarm limit. Any new value gets a p-value, a simple 0 to 1 measure of how unusual it is compared with the past.

For PLEX this suits small data: the hourly data audit and the learning loop for job pace have tens of past jobs, not thousands. Each new casing run, trip or BOP test can be scored against its own past jobs, and flagged when it falls outside the band instead of using a fixed percentage.

How: for each job type keep the last 20 to 30 durations, compute the median and sorted distances, and show the band (for example 90%) on the lookahead and an alert when a value falls outside it. The author warns that the band is only as good as the past jobs chosen, so exclude jobs with known breakdowns. Effort: one day in the engine.

Sources:
- [arXiv – Distribution-free process monitoring with conformal prediction](https://arxiv.org/abs/2512.23602)

## iPhone: any page can be a home-screen app

*New technology* – Since iOS 26, Safari opens anything added to the home screen as a full-screen web app and also supports WebGPU.

With iOS and iPadOS 26, adding a site to the home screen opens it as a web app by default; a manifest and service worker are no longer needed for that. Safari 26 also added WebGPU (graphics-card computing in the browser) and the File System WritableStream API for writing files.

For PLEX the bridge report page and the upload page can each be added as their own home-screen icon on the bridge and store phones, opening straight to the form without the main app. WebGPU on iPhone also makes in-browser models possible later: Transformers.js version 4 runs models on WebGPU and can cache them for offline use after the first download.

How: send the bridge team the report link and ask them to use Share › Add to Home Screen with Open as web app switched on. In-browser models are a later experiment, not urgent. Effort: minutes for the icons.
